# 大变更与单 PR 续审

维护日期：2026-10-15。依据当前工作区新增实现；最终全量验证结果见 [自审记录](review-self-audit.md) 与 [本次需求记录](../prd.md)。本文不代表真实模型或平台评论已验收。

## 调度与预算

GVS/infer 配置仍允许最多 100 个筛选后文件，每包最多 5 个文件片段、120000 字节，专业作业并发 4。600 次模型 HTTP 尝试、12000000 估算 Token、60 分钟是每个 PR 实际审核尝试的预算；费用预算为 0 时不启用金额限制。重试与备用模型仍计入同一 PR 预算，缓存命中不新增 HTTP 尝试、预留量或本轮 Usage。预算是保守估算，不能视为供应商账单硬上限。

同机各入口通过 `review.runtime_dir`（默认 `./data/review-runtime`，可用 `AGENT_REVIEW_RUNTIME_DIR` 覆盖）中的共享执行锁限制同时运行一个实际审核流水线。所有实例必须解析到同一共享目录；不同主机或不同目录没有该保障。每轮扫描最多启动一个实际流水线，未执行任务保留在持久清单中。队列优先上次尝试最早的任务，失败任务按重试时间恢复，避免反复失败的旧任务压住从未尝试的任务；其他仍存活实例拥有的队首任务等待该实例轮询。

模型顺序只有 Kimi → MiniMax。每个 PR 尝试建立新路由会话，优先检查 Kimi 可用性；该次尝试降级后不回跳。供应商冷却通过共享运行目录持久化，与响应检查点目录分离；全部可用供应商冷却时不探测新请求，允许复用已有成功响应。网络/暂时错误耗尽重试后可以降级，普通鉴权错误不能冒充配额耗尽。

## 完整输入与发布条件

- `PackBounded` 按模块、文件数量及字节预算分包。超大文件可以按完整 hunk 分片，每片保留原文件头、路径及新文件行号范围，新增/删除行数按片统计；原始文件 diff 保留供定位与确认使用。单个完整 hunk 连同文件头超预算仍明确失败，绝不静默截断。
- 关闭分包后整体超预算仍失败。总分析输入超预算时，逐包形成事实并分层归并为共用意图与约束；摘要无法容纳或归并无法缩小时失败，不以原始 diff 前缀替代全文。
- 最终确认每批最多 40 个唯一候选，system/user 消息正文合计最多 160000 字节，按实际 JSON 编码后文本检查。普通文件使用完整文件证据；编码后的完整文件超过 120000 字节时使用候选所在的完整 hunk，文件级候选需要全部 hunk。同批文件/hunk 证据只发送一次，候选通过 `evidence_ids` 引用共享证据。单候选所需完整证据无法容纳时失败。
- 候选 ID 由原问题生成；模型只能返回确认/驳回及原因，不能改写问题。未知/重复 ID、遗漏决定、缺少证据、任一专业作业失败、截断、预算或取消均阻止发布与成功基线推进。候选排序与反思前汇总包含完整内容的确定性比较，减少并发返回顺序对续审提示词和去重的影响。
- 分析字节统计覆盖原始筛选后 diff；确认字节统计是唯一实际提供的证据字节，可能只含候选相关 hunk，不代表确认模型重读全部 PR。模型读到文本也不能证明理解了全部业务影响。

## 恢复与版本

`review.checkpoint_dir` 默认 `./data/checkpoints`，CLI 显式 `-checkpoint-dir ""` 可关闭响应缓存；共享执行锁、任务清单和供应商冷却仍有效。GitHub、Codeup 分支/MR、本地 diff 各入口装配阶段响应检查点及固定知识快照。相同固定版本和配置/规则依赖可复用已接受结果；请求或身份变化失效，消费者拒绝结果会清除该响应。保存响应或知识检查点失败会阻断本次完成，不能标为成功。

MR 身份覆盖源/目标 SHA、元数据及配置依赖，不仅比较源 SHA。GitHub 使用固定 SHA compare，并在发布前复查版本、状态与元数据。任务旧版本完成不能覆盖队列中新版本。发布回执减少“评论成功、基线保存失败”后的重复评论，但远端成功与本地回执落盘仍不是原子操作。

## 验证和部署边界

本地回归包含完整多 hunk 分片、单 hunk 超限、后部差异、JSON 转义预算、共享确认与全部候选、非法/遗漏决定、单机跨进程互斥、队列公平和版本变更恢复。最终全量结果由主执行者记录；这些模拟用例不证明真实供应商配额、评论权限或缺陷检出率。

Windows 与 Linux 常驻入口及指定 MR 参数继续保留，操作见 [常驻审核一键启停](persistent-control.md)。现存真实进程未被停止、其运行二进制未被覆盖。切换前须停止全部旧审核实例，构建当前源码的新二进制，再重启；旧二进制不具备新增共享运行协议。Windows 原生验证与 Linux 交叉编译/Git Bash 路径验证应分别记录；没有原生 Linux 运行和 race 通过的结论。
