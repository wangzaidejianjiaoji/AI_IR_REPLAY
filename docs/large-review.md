# 大批量一次性审核

2026-10-14：GVS 和 gvs_infer 运行配置允许最多 100 个筛选后文件，仍使用一次性审核，不包含断点续跑。

## 配置

两套配置保持每包最多 5 文件、每包 diff 最多 120000 字节、专业作业并发 4。文件数保护上限改为 100；每个扫描轮次最多 600 次模型 HTTP 尝试、12000000 的保守输入/输出 Token 预留量、60 分钟。费用预算仍为 0，未启用账单金额限制。

调用和 Token 预算涵盖理解、分析、专业审核、确认以及重试，仍由整个扫描轮次共享。这些值允许更多工作，不保证每个 100 文件任务在供应商限额内成功。模型配额、账号权限、失败重试、其他 MR 和每个文件的实际 diff 大小均可能使轮次失败。提高预算可能增加费用。

## 全量输入与发布条件

- 专业审核按模块、文件数及 diff 字节数分包。文件内容不截断；单文件超过 120000 字节明确失败。暂不拆分单文件 hunk。
- 关闭分包时，整体 diff 超过预算也明确失败。
- 总 diff 超过分析预算时，每个包先建立变更事实，再按预算分层归并为所有审核角色共用的变更意图、模块及行为约束。未使用原 diff 的前缀代替全部输入。模型归纳仍不保证理解所有业务影响。
- 最终确认从完整 diff 中读取每个候选所属文件的原始证据。每批最多 40 个候选，system/user 文本总和最多 160000 字节；总候选数不再限制为 40。证据不能容纳在单批时明确失败，不裁切证据。JSON 转义和共享背景也计入该上限，因此源 diff 小于 120000 字节不保证确认请求一定能容纳。
- 缺少证据、未知/重复 ID、遗漏决定、失败的专业作业、截断的包以及预算/超时取消均阻止发布并阻止成功基线推进。
- 报告的分析输入统计涵盖全部筛选后 diff；确认字节统计只衡量候选所属文件的去重证据，不宣称最终确认重新阅读了全部 MR。
- 固定版本复查、dry-run 和评论开关保持原有行为。GVS/infer 当前配置允许发布 MR 评论。

## 验证

本地模拟测试覆盖 75 文件 MR 完整评论与基线推进、后部 diff 分析、45 个候选全部确认、按 JSON 编码后证据大小分批、遗漏决定拒绝发布、超大文件不调用模型、专业作业部分失败不发布及长源代码行不吞掉后续文件。

真实模型配额及真实 Codeup 评论成功需要实际运行日志确认，模拟测试不证明业务缺陷检出率。已知知识来源隔离测试失败不属于本次变更的修复范围。
