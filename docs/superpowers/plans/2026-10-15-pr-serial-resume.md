# 单 PR 续审实施计划

依据：2026-10-15 用户批准实施，并明确移除第二模型。优先级仅为 Kimi → MiniMax。

工作分为独立模块，按 subagent-driven-development 技能由独立实施者完成模型层和大变更层，主执行者负责调度、集成、文档，最后独立审查。

## 1. 模型与检查点

- [x] 先新增失败测试：每 PR 重新优先 Kimi、PR 内降级不回跳、额度冷却跨进程复用、网络重试耗尽降级、认证错误不冒充配额、全部不可用保存失败、取消停止派发。
- [x] 修改 internal/llm；保留现有主备字段，不增加第二模型。提供 WithReviewSession(ctx) 和独立的供应商冷却预检接口。响应检查点保留有效结果，不把失败标为成功。
- [x] 回归 llm 包；配置费用校验覆盖备用模型。记录实际语义与接口。

## 2. 大变更

- [x] 新增失败测试：完整多 hunk 文件超过预算可分片，单 hunk 超限拒绝，确认共享证据仅发送一次，候选排序稳定。
- [x] 修改 internal/packager、internal/coordinator：完整 hunk 分片与覆盖元数据、确认共享证据及编码后预算、确定性排序。适配已有模拟协议测试。
- [x] 回归 packager/coordinator；超限与遗漏仍失败关闭。

## 3. 串行与恢复集成

- [x] 新增失败测试：独立进程共用执行槽，每轮实际审核最多一个，旧成功基线不掩盖目标 SHA 变化，GitHub/分支检查点复用。
- [x] 新增共享审核槽、任务清单、冷却与稳定轮询顺序；配置 review.runtime_dir 默认项目 data/review-runtime；入口都在模型前获取同一 OS 锁。
- [x] 所有真实审核开启检查点、固定知识快照与 per-PR 预算/模型会话；保留原脚本和指定 MR 参数；失败不发布、不推进基线。
- [x] GitHub 快照及目标变更安全、MR 双 SHA 基线；配置默认启用续审并保证状态隔离。

## 4. 自审与交付

- [x] 独立审查并对可复现问题补回归修复；全量测试、适用的 race、脚本兼容与 Linux 交叉编译。
- [x] 更新部署/大变更说明，移除不再成立的旧结论；根目录写 prd.md，区分事实、设计约束和未验收项。
- [x] 不把明文凭据写入代码/文档或输出、不触发真实模型/评论、不终止正在运行的用户审核进程，不修改 outputs/wechat_article_learning。

Ruling：第二模型相关设计被用户明确撤销，实施中不添加相应接口或禁用占位。本次共享锁是单机共享路径保障，不宣称跨主机调度。

验收：最终全量 Go 测试、vet、PowerShell/Git Bash 兼容测试通过；Linux 交叉编译通过。race 因缺少 CGO 工具链未执行，原生 Linux 与真实平台待独立验收。
